# MSU Terrain — استخراج عوارض با DEM و DSM

برنامهٔ فارسی **کاملاً آفلاین و نصبی برای ویندوز ۶۴بیتی** برای استخراج پیکسل‌های مرتفع بر اساس **ارتفاع از زمینِ همان نقطه**، با انتخاب محدوده از شیپ‌فایل و پشتیبانی از TIFهای حجیم. تمام پردازش و نگهداری فایل‌ها روی دستگاه شماست. اینترنت، حساب کاربری، سرور ابری و کلید API لازم نیست.

## دانلود و اجرای نسخهٔ آفلاین ویندوز

[دانلود مستقیم نصاب Windows x64 نسخهٔ ۰٫۴ از GitHub](https://github.com/davidkordmir-source/MSU-DEM-DSM/raw/refs/tags/v0.4.0-desktop/downloads/MSU-Terrain-Setup-0.4.0-x64.exe)

1. فایل **`MSU-Terrain-Setup-0.4.0-x64.exe`** را دانلود و اجرا کنید. نصب نیز آفلاین است و دسترسی مدیر سیستم لازم ندارد.
2. برنامه را از میان‌بر **MSU Terrain** روی دسکتاپ یا منوی Start باز کنید. لوگوی اختصاصی روی برنامه، نصاب و میان‌بر قرار دارد.
3. رابط در پنجرهٔ مستقل Edge یا Chrome نصب‌شده روی دستگاه باز می‌شود؛ تب و نوار نشانی ندارد. اگر هیچ‌کدام موجود نباشد، مرورگر پیش‌فرض استفاده می‌شود. ارتباط برنامه فقط محلی است.
4. برای بستن برنامه دکمهٔ **خروج** را بزنید. حذف برنامه از Settings → Apps یا میان‌بر Uninstall در منوی Start انجام می‌شود.

**نصب جداگانهٔ Python، pip، uv یا کتابخانه لازم نیست**. Python رسمی، GDAL/PROJ و پایگاه مختصات، GEOS، همهٔ کتابخانه‌ها، قلم و رابط داخل نصاب هستند. ویندوز ۱۰ یا ۱۱ نسخهٔ x64 و یک مرورگر نصب‌شده لازم است؛ دستگاه ARM و ویندوز ۳۲بیتی هدف این بسته نیستند. نصب پیش‌فرض در پوشهٔ برنامه‌های کاربر است. نسخهٔ فعلی امضای دیجیتال ناشر ندارد.

برنامه فقط روی loopback گوش می‌دهد؛ در شبکهٔ محلی یا اینترنت سروری منتشر نمی‌کند. دانلود خودکار پایگاه مختصات PROJ غیرفعال است؛ درخواست‌های خارجی Python نیز در راه‌انداز آفلاین مسدود می‌شوند. فونت، اسکریپت و استایل از CDN دریافت نمی‌شوند. ساخت بسته در محیط توسعه به اینترنت نیاز دارد، اما **اولین اجرا و همهٔ اجراهای بعدی بستهٔ آماده آفلاین‌اند**.

برای کنترل سلامت نصاب می‌توانید فایل `.exe.sha256` موجود در `downloads/` را با SHA-256 دانلود مقایسه کنید. فهرست hash فایل‌های نصب‌شده در `MANIFEST.sha256.json` و مشخصات منابع رسمی در `DEPENDENCIES.json` قرار دارند. با دستور `runtime\python.exe -I offline_smoke.py` در پوشهٔ نصب، آزمون آفلاین محاسبات نیز اجرا می‌شود.

```text
height_above_ground = DSM − DEM
selected = height_above_ground > threshold_in_metres

DEM = −100 m, DSM = −50 m → height = 50 m → selected for threshold 30 m
```

## اجرای سورس برای توسعه‌دهندگان

Python 3.12 و [uv](https://docs.astral.sh/uv/getting-started/installation/) پیشنهاد می‌شود. در پوشهٔ پروژه:

```sh
uv sync --frozen
uv run --offline python -I run_offline.py
```

راه‌انداز یک پورت آزاد محلی انتخاب و مرورگر را باز می‌کند. برای پورت ثابت از `--port 8000` و برای جلوگیری از بازشدن خودکار مرورگر از `--no-browser` استفاده کنید. روی لینوکس یا macOS پس از نصب اولیهٔ وابستگی‌های توسعه، `bash run.sh` نیز همین کار را انجام می‌دهد و هیچ نصب یا دانلودی هنگام اجرا انجام نمی‌دهد. روش سورس به آماده‌سازی اولیه نیاز دارد؛ بستهٔ Windows x64 بالا تمام پیش‌نیازها را همراه دارد.

روش جایگزین بدون uv:

```sh
python -m venv .venv
# Linux/macOS:
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -I run_offline.py
# Windows: به جای .venv/bin/python از .venv\Scripts\python.exe استفاده کنید.
```

## استفاده

1. DEM زمین و DSM سطح را انتخاب کنید: GeoTIFF/BigTIFF تک‌باند ارتفاعی با پسوند `.tif` یا `.tiff` و CRS معتبر. **سقف ثابت حجم یا تعداد پیکسل وجود ندارد.** در نسخهٔ دسکتاپ روی محل انتخاب فایل کلیک کنید تا فایل مستقیم از دیسک و بدون کپی اضافه خوانده شود.
   پس از انتخاب، پیش‌نمایش همان فایل در «نمای منطقه» ظاهر می‌شود؛ تب‌های **DEM ورودی** و **DSM ورودی** مستقل از اجرای استخراج هستند. از بزرگ‌نمایی و جابه‌جایی برای بررسی تصویر استفاده کنید.
2. در صورت نیاز، محدودهٔ پردازش را از شیپ‌فایل تعیین کنید: یک ZIP شامل فایل‌های هم‌نام **SHP + SHX + DBF + PRJ**، یا انتخاب هم‌زمان همین فایل‌ها. CPG اختیاری است. فقط لایهٔ پلیگونی پذیرفته می‌شود.
3. واحد ارتفاع هر ورودی را تعیین کنید: متر، فوت بین‌المللی یا فوت پیمایشی آمریکا. `scale` و `offset` باند قبل از تبدیل واحد اعمال می‌شوند.
4. آستانهٔ ارتفاع از زمین را بر حسب متر وارد کنید. پیش‌فرض «بزرگ‌تر از» است؛ «بزرگ‌تر یا مساوی» نیز در دسترس است.
   شرط «بیشتر از ۳۰» هیچ سقف بالایی ندارد: ۳۱، ۵۰، ۲۰۰، ۱۰۰۰ و هر ارتفاع بالاتر انتخاب می‌شود. مقدار دقیقاً ۳۰ فقط در حالت «بزرگ‌تر یا مساوی» انتخاب می‌شود. انتهای نوار تنظیم سریع، حداکثر ارتفاع مجاز خروجی نیست.
5. یکسان بودن **مبنای ارتفاعی** فایل‌ها را تأیید کنید و تحلیل را اجرا کنید. مثلاً ارتفاع بیضوی و ارتفاع از سطح متوسط دریا باید پیش از استفاده به مبنای مشترک تبدیل شوند.
6. برای داده‌های حجیم، **انتخاب پوشهٔ نتایج** را بزنید و درایوی با فضای کافی انتخاب کنید. نتایج در زیرپوشهٔ جدا ذخیره می‌شوند و خودکار حذف نمی‌شوند. بدون انتخاب پوشه، نتایج موقت در محل پیش‌فرض برنامه قرار می‌گیرند.
7. لایهٔ ارتفاع نسبی، سطح DSM یا ماسک انتخاب را بررسی کنید. مرز محدوده طلایی است. با کشیدن نقشه جابه‌جا شوید و با دکمه‌ها یا چرخ ماوس بزرگ‌نمایی کنید. خروجی‌ها را جداگانه یا در ZIP دریافت کنید.

«امتحان با دادهٔ نمونه» دو مدل مصنوعی زیر سطح دریا تولید می‌کند و **همان مسیر محاسبهٔ واقعی** را اجرا می‌کند. این داده برداشت واقعی یک منطقه نیست.

مختصات شیپ‌فایل خودکار به CRS مدل سطح تبدیل می‌شود. تمام پلیگون‌های لایه با هم استفاده می‌شوند؛ هم‌پوشانی‌ها دوباره شمرده نمی‌شوند و حفره‌ها خارج از محدوده‌اند. مرکز پیکسل باید داخل محدوده باشد. خروجی به مستطیل پوشانندهٔ محدوده روی شبکهٔ DSM بریده می‌شود و بیرون پلیگون NoData است. بدون شیپ‌فایل، کل شبکهٔ DSM با احتساب پوشش مشترک معتبر پردازش می‌شود. محدودیت ۵۰ مگابایت فقط برای مجموعهٔ فایل‌های **شیپ‌فایل** است و به TIFها مربوط نیست.

## اختلاف تفکیک‌پذیری و سیستم مختصات

- شبکهٔ DSM مرجع است: CRS، جهت، اندازه و هم‌ترازی پیکسل‌های آن حفظ می‌شود. با شیپ‌فایل، ابعاد خروجی و مبدأ آن به محدودهٔ بریده‌شده تغییر می‌کند. خود DSM بازنمونه‌برداری نمی‌شود.
- DEM روی شبکهٔ DSM بازنمونه‌برداری و در صورت نیاز تبدیل مختصات می‌شود. در حالت خودکار، DEM درشت‌تر با **bilinear** و DEM ریزتر با **average** تبدیل می‌شود. با CRS متفاوت، اندازهٔ تقریبی پیکسل DEM در CRS مقصد برای انتخاب روش استفاده می‌شود. انتخاب دستی bilinear، average و nearest نیز ممکن است.
- شبکه‌های یکسان بدون درون‌یابی خوانده می‌شوند. اختلاف مکان پیکسل‌ها حتی در اندازهٔ برابر نیازمند هم‌مکان‌سازی است.
- DEM ده‌متری و DSM نیم‌متری خروجی نیم‌متری می‌دهند. **تفکیک‌پذیری خروجی به معنی دقت واقعی نیم‌متری DEM نیست.** خطای زمین می‌تواند باعث انتخاب یا حذف عوارض نزدیک آستانه شود.
- فقط پیکسل‌های معتبر در هر دو ورودی محاسبه می‌شوند. NoData، ماسک اعتبار داخلی GeoTIFF، NaN، Inf و نواحی بدون پوشش مشترک حذف می‌شوند. ماسک خارجی و فایل‌های جانبی در ورودی تک‌فایلی پشتیبانی نمی‌شوند.
- محاسبه با float64 انجام و خروجی ارتفاع با float32 ذخیره می‌شود. حاشیه‌ای در حد گردکردن float64 مانع عبور اشتباه مقدار دقیق آستانه هنگام درون‌یابی می‌شود.
- مساحت گزارش‌شده در CRS تصویرشده، مساحت شبکه‌ای با تبدیل واحد افقی به متر است؛ برای CRS جغرافیایی گزارش نمی‌شود. این عدد مساحت ژئودزیک یا شیب‌دار نیست.

## خروجی‌ها

| فایل | محتوا |
| --- | --- |
| `features.zip` | خروجی اصلی برداری: اجزای شیپ‌فایل و گزارش، همراه جدول ویژگی‌ها |
| `features_001.shp / .shx / .dbf / .prj / .cpg` | پلیگون عوارض منتخب، جدول ویژگی‌های هر عارضه و تعریف CRS؛ همهٔ اجزا باید کنار هم بمانند |
| `height.tif` | تمام ارتفاع‌های معتبر `DSM − DEM` بر حسب متر؛ مقادیر منفی حفظ می‌شوند؛ NoData برابر NaN |
| `extracted.tif` | ارتفاع از زمین فقط برای پیکسل‌های عبورکرده از آستانه؛ سایر پیکسل‌ها NaN |
| `mask.tif` | ۱ منتخب، ۰ معتبر و غیرمنتخب، ۲۵۵ نامعتبر یا فاقد هم‌پوشانی |
| `report.json` | آمار، آستانه، روش تبدیل، مشخصات ورودی‌ها، منابع و محدودیت‌ها |
| `results.zip` | شیپ‌فایل‌ها، سه رستر کمکی و گزارش؛ در هنگام دانلود ساخته می‌شود |

هر مجموعهٔ پیکسل منتخب که با لبه به هم متصل باشند، یک عارضهٔ برداری است؛ تماس فقط در گوشه، عارضهٔ جدا می‌سازد. مرزها از لبهٔ پیکسل‌های DSM ساخته می‌شوند؛ حفره‌ها حفظ و قطعات دو سوی مرز پردازش به هم متصل می‌شوند. هندسه ساده‌سازی یا گرد نمی‌شود. اگر هیچ پیکسلی انتخاب نشود، یک لایهٔ خالی معتبر دریافت می‌کنید.

| فیلد DBF | معنی |
| --- | --- |
| `OBJ_ID` | شناسهٔ یکتای عارضه |
| `PIXELS` | تعداد پیکسل‌های منتخب عارضه |
| `H_MIN_M` / `H_MAX_M` / `H_MEAN_M` | کمترین، بیشترین و میانگین **ارتفاع از زمین** بر حسب متر |
| `AREA_M2` | مساحت شبکه‌ای بر حسب مترمربع؛ در CRS جغرافیایی خالی است |
| `THRESH_M` / `RULE` | آستانهٔ ارتفاع و شرط `>` یا `>=` |

نمونهٔ ۲۰ ردیف اول جدول در رابط دیده می‌شود؛ تمام ردیف‌ها در DBF قرار دارند. نام فیلدها مطابق محدودیت نام‌گذاری Shapefile کوتاه‌اند. برای سازگاری با نرم‌افزارهای GIS، خروجی پیش از رسیدن اجزای SHP/DBF به محدودیت ۲ گیگابایت در لایه‌های شماره‌دار بعدی ادامه می‌یابد؛ شناسه‌ها در همهٔ لایه‌ها یکتا می‌مانند. یک عارضهٔ منفرد با مرز بسیار پیچیده نیز تابع ظرفیت این فرمت و حافظهٔ لازم برای هندسه است.

ارتفاع به‌تنهایی **ساختمان را از درخت و دیگر عوارض بلند تفکیک نمی‌کند**؛ شیپ‌فایل خروجی، مرز ناحیه‌های عبورکرده از شرط ارتفاع است. تشخیص نوع عارضه به دادهٔ مکمل یا مدل طبقه‌بندی نیاز دارد.

## کارایی و منابع

- TIF و BigTIFF سقف ثابت حجم ندارند. انتخاب مستقیم در نسخهٔ دسکتاپ، رستر را بدون بارگذاری HTTP و کپی موقت می‌خواند. کشیدن و رهاکردن فایل یا اجرای مرورگری سورس از مسیر بارگذاری قطعه‌ای استفاده می‌کند و فضای موقت اضافه لازم دارد.
- فایل‌های ۱۰۰ گیگابایتی و بزرگ‌تر از مسیر انتخاب مستقیم قابل خواندن‌اند؛ کل فایل در RAM یا مرورگر کپی نمی‌شود. فایل‌های حجیم باید BigTIFF معتبر باشند. سرعت خواندن به ساختار داخلی TIFF، اندازهٔ بلوک‌ها، فشرده‌سازی و دیسک بستگی دارد؛ رستر بلوک‌بندی‌شده برای این کار مناسب‌تر است.
- فضای آزاد دیسک و توان واقعی سیستم همچنان تعیین‌کننده‌اند. پیش از پردازش، ظرفیت سه رستر خروجی به‌صورت محافظه‌کارانه با ۹ بایت به‌ازای هر پیکسل، به‌علاوه فضای کمکی، بررسی می‌شود. خروجی‌ها ممکن است از ورودی فشرده بزرگ‌تر شوند؛ پوشهٔ نتایج را روی درایو مناسب انتخاب کنید. انتخاب محدوده با شیپ‌فایل حجم پردازش و خروجی را کم می‌کند. خروجی‌های بزرگ در قالب BigTIFF نوشته می‌شوند.
- ZIP فقط هنگام دانلود، به‌صورت جریانی و با پشتیبانی ZIP64 ساخته می‌شود. یک ZIP اضافی روی دیسک پردازش ساخته نمی‌شود و انتظار برای بسته‌بندی کامل هم لازم نیست. فایل‌های داخل پوشهٔ انتخابی بدون دانلود مجدد قابل استفاده‌اند.
- تعداد هسته‌های CPU از affinity و محدودیت cgroup استخراج می‌شود. GDAL برای بازنمونه‌برداری و فشرده‌سازی از هسته‌های در دسترس استفاده می‌کند.
- پردازش در پنجره‌های ۱۰۲۴ × ۱۰۲۴ است (۵۱۲ در حافظهٔ کمتر از ۲ گیگابایت)؛ کل رستر در حافظه بارگذاری نمی‌شود.
- ساخت شیپ‌فایل در قطعات ۲۵۶ × ۲۵۶ با نگهداری اتصال‌ها و قطعات روی دیسک در SQLite انجام می‌شود. مرزها در پایان برای هر عارضه ادغام می‌شوند؛ فایل موقت حذف می‌شود. علاوه بر ظرفیت رسترها، شیپ‌فایل و پایگاه موقت فضای دیسک لازم دارند که به پیچیدگی عوارض بستگی دارد.
- کش GDAL حداکثر ۲۵٪ حافظه تا سقف ۴ گیگابایت و حافظهٔ warping حداکثر ۱۲٫۵٪ تا سقف یک گیگابایت است. بودجه برای جلوگیری از مصرف تمام RAM محدود می‌شود.
- یک کار پردازشی در هر لحظه اجرا می‌شود. حداکثر سه کار، شامل بارگذاری و کار جاری، پذیرفته می‌شود. Uvicorn را با **یک worker** اجرا کنید.
- نمایش نقشه با WebGL، `powerPreference: high-performance`، نسبت پیکسل دستگاه و رسم فقط هنگام تغییر انجام می‌شود. انتخاب واقعی GPU به مرورگر و سخت‌افزار بستگی دارد؛ حالت Canvas برای نبود WebGL وجود دارد. پردازش ژئورستری با CPU انجام می‌شود و این برنامه از CUDA استفاده نمی‌کند.
- پیش‌نمایش حداکثر ۲۰۴۸ پیکسل در ضلع بلند است (۱۰۲۴ در سیستم کم‌حافظه)؛ GeoTIFF خروجی کاهش تفکیک‌پذیری ندارد. رنگ‌ها برای نمایش کشیده می‌شوند و جایگزین مقدار عددی رستر نیستند. عوارض کوچک ممکن است در پیش‌نمایش کاهش‌یافته دیده نشوند.
- پیش‌نمایش **ورودی** از Overview داخلی استفاده می‌کند، یا برای فایل‌های کوچک مستقیماً تا ضلع ۷۶۸ پیکسل خوانده می‌شود. در فایل بزرگ بدون Overview، نمای سریع با نمونه‌برداری از تعداد محدودی بلوک ساخته می‌شود و ممکن است جزئیات کوچک یا نواحی کم‌پوشش را نشان ندهد. وضوح پیش‌نمایش روی دقت استخراج و شیپ‌فایل اثر ندارد. ورودی اصلی برای ساخت Overview تغییر داده نمی‌شود.
- استفادهٔ دائمی از ۱۰۰٪ CPU/GPU تضمین نمی‌شود؛ سرعت به دیسک، فشرده‌سازی، روش تبدیل و اندازهٔ منطقه بستگی دارد.

## داده‌های موقت و استقرار

نسخهٔ نصبی نتایج موقت را در `%LOCALAPPDATA%\MSU Terrain\results` و گزارش اجرا را در `application.log` همان پوشهٔ برنامه ذخیره می‌کند. فایل‌های اصلی DEM/DSM هرگز حذف یا تغییر داده نمی‌شوند. انتخاب مستقیم دسکتاپ کپی ورودی ایجاد نمی‌کند. بارگذاری مرورگری یک بار انجام می‌شود و همان کپی برای پیش‌نمایش و استخراج دوباره استفاده می‌شود. کپی‌های بارگذاری‌شده، پیش‌نمایش‌ها و خروجی‌های موقت قدیمی‌تر از ۲۴ ساعت هنگام پذیرش کار بعدی پاک‌سازی می‌شوند؛ کارهای فعال مستثنا هستند. نتایج پوشهٔ انتخابی دائمی‌اند. حذف برنامه فایل‌های اصلی، خروجی‌های دریافت‌شده و داده‌های AppData را نگه می‌دارد. نسخهٔ سورس از `.data/` استفاده می‌کند و متغیر اختیاری `MSU_DATA_DIR` مسیر را تغییر می‌دهد.

این نسخه برای استفادهٔ شخصی یا محیط مورداعتماد آماده شده است. برای انتشار عمومی، احراز هویت، سهمیهٔ کاربران، محدودیت درخواست در reverse proxy و سیاست نگهداری داده اضافه کنید. در محیط ابری از checkout موجود استفاده کنید؛ ایجاد Git worktree نیاز نیست. فرآیند سرور پس از بازیابی snapshot باید دوباره اجرا شود.

## آزمون‌ها

```sh
uv sync --frozen
uv run pytest -q
uv run ruff check app tests
```

آزمون‌ها شامل ارتفاع منفی از سطح دریا، مرز آستانه، NoData، ماسک داخلی، واحد فوت و scale/offset، تبدیل ۱۰ متر و نیم‌متر، CRS متفاوت، شیپ‌فایل و حفره‌ها، فایل خراب، API، ZIP64 جریانی و حفظ پوشهٔ خروجی هستند. آزمون مقیاس بزرگ، فایل sparse با اندازهٔ منطقی ۱۲۸ گیبی‌بایت و پردازش محدوده‌ای از شبکهٔ BigTIFF با بیش از ۳۴ میلیارد پیکسل را بررسی می‌کند. این فایل‌های آزمایشی فضای واقعی کمی اشغال می‌کنند؛ آزمون حاضر سنجش سرعت پردازش کامل ۱۰۰ گیگابایت دادهٔ واقعی نیست.

آزمون مرورگر در حالی که برنامه با `--port 8000 --no-browser` اجراست:

```sh
uv sync --frozen --group browser
# Chromium موجود استفاده می‌شود؛ مسیر پیش‌فرض /usr/bin/chromium است.
# متغیر CHROMIUM_PATH مسیر اجرایی دیگری را تعیین می‌کند.
uv run --group browser python tests/browser_smoke.py
```

آزمون مرورگر درخواست‌های خارجی را مسدود می‌کند و نمونه، بارگذاری واقعی DEM ده‌متری/DSM نیم‌متری، محدوده از ZIP و اجزای شیپ‌فایل، مقادیر رستر خروجی، دریافت ZIP، بازیابی پس از refresh، اعتبارسنجی، تغییر لایه، بزرگ‌نمایی و چهار عرض نمایش را بررسی می‌کند. تصاویر در `test-results/` ذخیره می‌شوند. WebGL در headless ممکن است از renderer نرم‌افزاری استفاده کند؛ عبور این آزمون بنچمارک GPU فیزیکی نیست.

## بازسازی بستهٔ ویندوز

```sh
# Linux build host: Python 3.12, MinGW-w64, NSIS >= 3.11
python tools/build_installer.py
```

این مرحله مخصوص سازنده و نیازمند اینترنت برای دریافت اولیهٔ منابع است. ابزار از NuGet رسمی Python Software Foundation و PyPI دانلود می‌کند و hashهای قفل‌شده در `packaging/windows-lock.json` را کنترل می‌کند. راه‌انداز بومی x64 با MinGW و آیکون برنامه ساخته می‌شود؛ NSIS نصاب و حذف‌کنندهٔ آفلاین را در `downloads/` تولید می‌کند. `--cache` محل منابع ذخیره‌شده و `--tool-root` ریشهٔ ابزارهای Debian استخراج‌شده را می‌پذیرد. برای بستهٔ ZIP نیز `tools/build_windows_bundle.py` در دسترس است. هیچ دادهٔ کاربر، محیط مجازی توسعه یا تنظیمات احراز هویت داخل نصاب قرار نمی‌گیرد.
