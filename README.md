# MSU Terrain — استخراج عوارض از یک DSM

برنامهٔ فارسی **کاملاً آفلاین و نصبی برای ویندوز ۶۴بیتی** برای استخراج پیکسل‌های مرتفع بر اساس **ارتفاع از زمینِ تخمین‌زده‌شده در همان نقطه**، با انتخاب محدوده از شیپ‌فایل و پشتیبانی از TIFهای حجیم. تمام پردازش و نگهداری فایل‌ها روی دستگاه شماست. اینترنت، حساب کاربری، سرور ابری و کلید API لازم نیست.

## دانلود و اجرای نسخهٔ آفلاین ویندوز

[دانلود مستقیم نصاب Windows x64 نسخهٔ ۰٫۵ از GitHub](https://github.com/davidkordmir-source/MSU-DEM-DSM/raw/refs/tags/v0.5.0-desktop/downloads/MSU-Terrain-Setup-0.5.0-x64.exe)

1. فایل **`MSU-Terrain-Setup-0.5.0-x64.exe`** را دانلود و اجرا کنید. نصب نیز آفلاین است و دسترسی مدیر سیستم لازم ندارد.
2. برنامه را از میان‌بر **MSU Terrain** روی دسکتاپ یا منوی Start باز کنید. لوگوی اختصاصی روی برنامه، نصاب و میان‌بر قرار دارد.
3. رابط در پنجرهٔ مستقل Edge یا Chrome نصب‌شده روی دستگاه باز می‌شود؛ تب و نوار نشانی ندارد. اگر هیچ‌کدام موجود نباشد، مرورگر پیش‌فرض استفاده می‌شود. ارتباط برنامه فقط محلی است.
4. برای بستن برنامه دکمهٔ **خروج** را بزنید. حذف برنامه از Settings → Apps یا میان‌بر Uninstall در منوی Start انجام می‌شود.

**نصب جداگانهٔ Python، pip، uv یا کتابخانه لازم نیست**. Python رسمی، GDAL/PROJ و پایگاه مختصات، GEOS و SciPy، همهٔ کتابخانه‌ها، قلم و رابط داخل نصاب هستند. ویندوز ۱۰ یا ۱۱ نسخهٔ x64 و یک مرورگر نصب‌شده لازم است؛ دستگاه ARM و ویندوز ۳۲بیتی هدف این بسته نیستند. نصب پیش‌فرض در پوشهٔ برنامه‌های کاربر است. نسخهٔ فعلی امضای دیجیتال ناشر ندارد.

برنامه فقط روی loopback گوش می‌دهد؛ در شبکهٔ محلی یا اینترنت سروری منتشر نمی‌کند. دانلود خودکار پایگاه مختصات PROJ غیرفعال است؛ درخواست‌های خارجی Python نیز در راه‌انداز آفلاین مسدود می‌شوند. فونت، اسکریپت و استایل از CDN دریافت نمی‌شوند. ساخت بسته در محیط توسعه به اینترنت نیاز دارد، اما **اولین اجرا و همهٔ اجراهای بعدی بستهٔ آماده آفلاین‌اند**.

برای کنترل سلامت نصاب می‌توانید فایل `.exe.sha256` موجود در `downloads/` را با SHA-256 دانلود مقایسه کنید. فهرست hash فایل‌های نصب‌شده در `MANIFEST.sha256.json` و مشخصات منابع رسمی در `DEPENDENCIES.json` قرار دارند. با دستور `runtime\python.exe -I offline_smoke.py` در پوشهٔ نصب، آزمون آفلاین محاسبات نیز اجرا می‌شود.

```text
estimated_ground = local_ground_estimate(DSM)
height_above_ground = DSM − estimated_ground
selected = height_above_ground > threshold_in_metres

estimated_ground = −100 m, DSM = −50 m → height = 50 m → selected for threshold 30 m
```

## اجرای سورس برای توسعه‌دهندگان

Python 3.12 و [uv](https://docs.astral.sh/uv/getting-started/installation/) پیشنهاد می‌شود. در پوشهٔ پروژه:

```sh
uv sync --frozen
uv run --offline python -I run_offline.py
```

راه‌انداز یک پورت آزاد محلی انتخاب و مرورگر را باز می‌کند. برای پورت ثابت از `--port 8000` و برای جلوگیری از بازشدن خودکار مرورگر از `--no-browser` استفاده کنید. روی لینوکس یا macOS پس از نصب اولیهٔ وابستگی‌های توسعه، `bash run.sh` نیز همین کار را انجام می‌دهد و هیچ نصب یا دانلودی هنگام اجرا انجام نمی‌دهد. روش سورس به آماده‌سازی اولیه نیاز دارد؛ بستهٔ Windows x64 بالا تمام پیش‌نیازها را همراه دارد.

روش جایگزین بدون uv:

```sh
python -m venv .venv
# Linux/macOS:
.venv/bin/python -m pip install --require-hashes -r requirements.txt
.venv/bin/python -I run_offline.py
# Windows: به جای .venv/bin/python از .venv\Scripts\python.exe استفاده کنید.
```

## استفاده

1. فقط **یک DSM** انتخاب کنید: GeoTIFF/BigTIFF تک‌باند ارتفاعی با پسوند `.tif` یا `.tiff` و CRS معتبر. DEM لازم نیست. **سقف ثابت حجم یا تعداد پیکسل وجود ندارد.** در نسخهٔ دسکتاپ روی محل انتخاب فایل کلیک کنید تا مستقیم از دیسک و بدون کپی خوانده شود. پیش‌نمایش ورودی پیش از استخراج، خودکار در «نمای منطقه» ظاهر می‌شود.
2. برای محدود کردن خروجی، یک ZIP شامل **SHP + SHX + DBF + PRJ** هم‌نام یا همین اجزا را هم‌زمان انتخاب کنید. CPG اختیاری است. لایه باید پلیگونی باشد. برنامه برای تخمین زمین، DSM اطراف محدوده را هم می‌خواند.
3. واحد ارتفاع DSM را مشخص کنید: متر، فوت بین‌المللی یا فوت پیمایشی آمریکا. ضریب `scale` و `offset` باند اعمال می‌شود. مقادیر مثبت و منفی ارتفاع مطلق پذیرفته می‌شوند.
4. ارتفاع دلخواه **از زمین** را بر حسب متر وارد کنید. پیش‌فرض، شرط سخت `>` است. «بالاتر از ۳۰» شامل ۳۱، ۵۰، ۲۰۰، ۱۰۰۰ و تمام ارتفاع‌های بیشتر است؛ سقف بالایی وجود ندارد. مقدار دقیقاً ۳۰ فقط با گزینهٔ مساوی انتخاب می‌شود. انتهای نوار تنظیم سریع، سقف ارتفاع استخراج نیست.
5. پیش‌فرض نوع زمین **شهری و هموار** است. عرض بزرگ‌ترین عارضه یا بلوک متراکم را کمی بزرگ‌تر از پهن‌ترین ساختمان یا پوشش پیوسته بگذارید (پیش‌فرض ۲۰۰ متر). مقدار کم ممکن است سقف را زمین حساب کند؛ مقدار زیاد ممکن است ناهمواری واقعی زمین را حذف کند. این عرض، فیلتر اندازهٔ عوارض خروجی نیست.
6. گام پیش‌فرض تخمین زمین ۲ متر است. مقدار کوچک‌تر جزئیات زمین و هزینهٔ پردازش را افزایش می‌دهد؛ گام واقعی از تفکیک‌پذیری DSM ریزتر نمی‌شود و برای عرض‌های بسیار بزرگ، خودکار افزایش می‌یابد. **استخراج نهایی همیشه روی شبکهٔ اصلی DSM** است.
7. **انتخاب پوشهٔ نتایج** را بزنید و درایوی با فضای کافی تعیین کنید. نتایج در زیرپوشهٔ جدا ذخیره می‌شوند و خودکار حذف نمی‌شوند. بدون انتخاب پوشه، خروجی‌ها موقت‌اند.
8. تحلیل را اجرا کنید. لایهٔ **زمین تخمینی**، ارتفاع نسبی و عوارض منتخب را بررسی و **شیپ‌فایل + ویژگی‌ها** را دریافت کنید. مدل زمین و کدهای پشتیبانی نیز قابل دریافت‌اند.

«امتحان با دادهٔ نمونه» یک شهر مصنوعی و هموار در ارتفاع ۱۰۰− متر می‌سازد و مسیر تک‌DSM را اجرا می‌کند. این داده برداشت واقعی یک منطقه نیست.

CRS شیپ‌فایل خودکار تبدیل می‌شود. تمام پلیگون‌ها استفاده می‌شوند؛ هم‌پوشانی‌ها دوباره شمرده نمی‌شوند و حفره‌ها خارج از محدوده‌اند. خروجی به کادر محدوده روی شبکهٔ DSM بریده می‌شود؛ فقط مرکز پیکسل‌های داخل مرز معتبر است. بدون محدوده، کل DSM پردازش می‌شود. محدودیت ۵۰ مگابایت فقط برای فایل‌های **محدودهٔ ورودی** است و به TIF یا شیپ‌فایل خروجی مربوط نیست.

## تخمین زمین و حدود دقت

**DSM زمین پنهان زیر ساختمان و پوشش گیاهی را اندازه‌گیری نمی‌کند. از یک DSM به‌تنهایی نمی‌توان ارتفاع واقعی همهٔ عوارض را تضمین کرد.** این روش الزاماً از یک DEM معتبر دقیق‌تر نیست. برای مثال، یک DSM که فقط سقف صاف را پوشش می‌دهد، از یک قطعهٔ زمین صاف قابل تشخیص نیست. ساختمان‌های پهن‌تر از عرض تنظیم‌شده، بلوک متراکم، جنگل، آب، لبهٔ فایل، اختلاف زمان برداشت، نقاط پرت، شیب و صخره‌ها می‌توانند نتیجه را تغییر دهند. کیفیت داده و تنظیم NoData باید بررسی شود. هدف نرم‌افزار استخراج ارتفاع تخمینی است؛ کاهش خطای دادهٔ واقعی کاربر بدون نمونهٔ مرجع ارزیابی نشده است.

روش نسخهٔ فعلی:

- DSM روی شبکهٔ متری درشت‌تر با میانگین‌گیری نمونه‌برداری می‌شود. در CRS تصویرشده، شبکه به مبدأ DSM متصل است. برای CRS جغرافیایی، تصویر متری محلی UTM یا قطبی به کار می‌رود؛ برای مناطق بسیار وسیع، برش‌های محلی مناسب‌ترند.
- بازشدگی مورفولوژیک در چند اندازه، نقاط احتمالی زمین را از برجستگی‌ها جدا می‌کند. آستانهٔ اختلاف با توجه به نوع زمین و اندازهٔ پنجره تعیین می‌شود. این پیاده‌سازی، روش اختصاصی چندمقیاسی است و معادل تأییدشدهٔ یک الگوریتم مرجع یا مدل یادگیری ماشین نیست.
- زمین زیر برجستگی‌ها با برازش صفحه به نقاط احتمالی زمین در همسایگی تخمین زده می‌شود. تمام مراحل قطعه‌ای‌اند و هر قطعه حاشیهٔ همپوشان برای فیلتر و برازش دارد؛ به مثلث‌بندی سراسری یا بارگذاری کل رستر نیاز نیست. در نبود پشتیبانی کافی، برآورد جایگزین با کد محدودیت ثبت می‌شود.
- زمین تخمینی با درون‌یابی دوخطی به شبکهٔ اصلی DSM منتقل می‌شود؛ ارتفاع نسبی از تفاضل DSM اصلی و زمین به دست می‌آید. این تبدیل، دقت واقعی مدل زمین را افزایش نمی‌دهد. خطای زمین می‌تواند عوارض نزدیک آستانه را انتخاب یا حذف کند.
- `ground.tif` ارتفاع **مطلق زمین تخمینی** بر حسب متر است و کادر آن برای درون‌یابی کمی از AOI بزرگ‌تر است. `ground.png` در پیش‌نمایش به شبکهٔ خروجی هم‌تراز می‌شود.
- `ground_quality.tif` تشخیص داخلی پشتیبانی مدل است: **۰ نامعتبر، ۱ نقطهٔ احتمالی زمین، ۲ برازش صفحهٔ محلی، ۳ پشتیبانی محدود**. این کدها احتمال آماری صحت نیستند و کد ۱ یا ۲ تضمین نمی‌کند که زمین واقعی پیدا شده است. عوارض با پشتیبانی محدود خودکار حذف نمی‌شوند؛ تعداد پیکسل‌های منتخب آن‌ها در `WEAK_PX` می‌آید.
- CRS، جهت و اندازهٔ پیکسل خروجی همان DSM است. دادهٔ اصلی DSM برای انتخاب عوارض بازنمونه‌برداری نمی‌شود. NoData، ماسک داخلی، NaN و Inf انتخاب نمی‌شوند؛ ماسک خارجی و فایل جانبی در ورودی تک‌فایلی پشتیبانی نمی‌شود.
- محاسبات با float64 و ذخیرهٔ مدل زمین و ارتفاع با float32 است؛ حاشیهٔ گردکردن در مقایسه لحاظ می‌شود، اما جای خطای واقعی تخمین زمین را نمی‌گیرد. مقادیر منفی اختلاف برای بررسی در `height.tif` حفظ می‌شوند.
- مساحت در CRS تصویرشده با تبدیل واحد افقی به متر گزارش می‌شود؛ مساحت شبکه‌ای است، نه ژئودزیک یا سطح شیب‌دار. در CRS جغرافیایی مساحت خالی می‌ماند.

## خروجی‌ها

| فایل | محتوا |
| --- | --- |
| `features.zip` | خروجی اصلی برداری: اجزای شیپ‌فایل و گزارش، همراه جدول ویژگی‌ها |
| `features_001.shp / .shx / .dbf / .prj / .cpg` | پلیگون عوارض منتخب، جدول ویژگی‌های هر عارضه و تعریف CRS؛ همهٔ اجزا باید کنار هم بمانند |
| `height.tif` | تمام ارتفاع‌های معتبر `DSM − estimated ground` بر حسب متر؛ مقادیر منفی حفظ می‌شوند؛ NoData برابر NaN |
| `extracted.tif` | ارتفاع از زمین فقط برای پیکسل‌های عبورکرده از آستانه؛ سایر پیکسل‌ها NaN |
| `mask.tif` | ۱ منتخب، ۰ معتبر و غیرمنتخب، ۲۵۵ نامعتبر یا فاقد هم‌پوشانی |
| `ground.tif` | زمین تخمینی بر حسب متر، با ارتفاع مطلق مثبت یا منفی |
| `ground_quality.tif` | کد پشتیبانی مدل زمین، از ۰ تا ۳ |
| `report.json` | آمار، آستانه، پارامترهای تخمین زمین، مشخصات ورودی، منابع و محدودیت‌ها |
| `results.zip` | شیپ‌فایل‌ها، پنج رستر و گزارش؛ در هنگام دانلود ساخته می‌شود |

هر مجموعهٔ پیکسل منتخب که با لبه به هم متصل باشند، یک عارضهٔ برداری است؛ تماس فقط در گوشه، عارضهٔ جدا می‌سازد. مرزها از لبهٔ پیکسل‌های DSM ساخته می‌شوند؛ حفره‌ها حفظ و قطعات دو سوی مرز پردازش به هم متصل می‌شوند. هندسه ساده‌سازی یا گرد نمی‌شود. اگر هیچ پیکسلی انتخاب نشود، یک لایهٔ خالی معتبر دریافت می‌کنید.

| فیلد DBF | معنی |
| --- | --- |
| `OBJ_ID` | شناسهٔ یکتای عارضه |
| `PIXELS` | تعداد پیکسل‌های منتخب عارضه |
| `H_MIN_M` / `H_MAX_M` / `H_MEAN_M` | کمترین، بیشترین و میانگین **ارتفاع از زمین** بر حسب متر |
| `AREA_M2` | مساحت شبکه‌ای بر حسب مترمربع؛ در CRS جغرافیایی خالی است |
| `THRESH_M` / `RULE` | آستانهٔ ارتفاع و شرط `>` یا `>=` |
| `GND_SRC` | `DSM_EST`: زمین تخمینی از DSM؛ `DEM`: زمین خارجی در مسیر قدیمی API |
| `WEAK_PX` | تعداد پیکسل منتخب با پشتیبانی محدود مدل زمین؛ صفر تضمین صحت نیست |

نمونهٔ ۲۰ ردیف اول جدول در رابط دیده می‌شود؛ تمام ردیف‌ها در DBF قرار دارند. نام فیلدها مطابق محدودیت نام‌گذاری Shapefile کوتاه‌اند. برای سازگاری با نرم‌افزارهای GIS، خروجی پیش از رسیدن اجزای SHP/DBF به محدودیت ۲ گیگابایت در لایه‌های شماره‌دار بعدی ادامه می‌یابد؛ شناسه‌ها در همهٔ لایه‌ها یکتا می‌مانند. یک عارضهٔ منفرد با مرز بسیار پیچیده نیز تابع ظرفیت این فرمت و حافظهٔ لازم برای هندسه است.

ارتفاع به‌تنهایی **ساختمان را از درخت و دیگر عوارض بلند تفکیک نمی‌کند**؛ شیپ‌فایل خروجی، مرز ناحیه‌های عبورکرده از شرط ارتفاع است. تشخیص نوع عارضه به دادهٔ مکمل یا مدل طبقه‌بندی نیاز دارد.

## کارایی و منابع

- TIF و BigTIFF سقف ثابت حجم ندارند. انتخاب مستقیم در نسخهٔ دسکتاپ، رستر را بدون بارگذاری HTTP و کپی موقت می‌خواند. کشیدن و رهاکردن فایل یا اجرای مرورگری سورس از مسیر بارگذاری قطعه‌ای استفاده می‌کند و فضای موقت اضافه لازم دارد.
- فایل‌های ۱۰۰ گیگابایتی و بزرگ‌تر از مسیر انتخاب مستقیم قابل خواندن‌اند؛ کل فایل در RAM یا مرورگر کپی نمی‌شود. فایل‌های حجیم باید BigTIFF معتبر باشند. سرعت خواندن به ساختار داخلی TIFF، اندازهٔ بلوک‌ها، فشرده‌سازی و دیسک بستگی دارد؛ رستر بلوک‌بندی‌شده برای این کار مناسب‌تر است.
- فضای آزاد دیسک و توان واقعی سیستم همچنان تعیین‌کننده‌اند. پیش از پردازش، ظرفیت سه رستر خروجی به‌صورت محافظه‌کارانه با ۹ بایت به‌ازای هر پیکسل، به‌علاوه فضای کمکی، بررسی می‌شود. مدل زمین و کدهای آن نیز ۵ بایت به‌ازای هر پیکسل شبکهٔ تخمین، به‌علاوه فضای کمکی، نیاز دارند. خروجی‌ها ممکن است از ورودی فشرده بزرگ‌تر شوند؛ پوشهٔ نتایج را روی درایو مناسب انتخاب کنید. انتخاب محدوده با شیپ‌فایل حجم پردازش و خروجی را کم می‌کند. خروجی‌های بزرگ در قالب BigTIFF نوشته می‌شوند.
- ZIP فقط هنگام دانلود، به‌صورت جریانی و با پشتیبانی ZIP64 ساخته می‌شود. یک ZIP اضافی روی دیسک پردازش ساخته نمی‌شود و انتظار برای بسته‌بندی کامل هم لازم نیست. فایل‌های داخل پوشهٔ انتخابی بدون دانلود مجدد قابل استفاده‌اند.
- تعداد هسته‌های CPU از affinity و محدودیت cgroup استخراج می‌شود. GDAL برای بازنمونه‌برداری و فشرده‌سازی از هسته‌های در دسترس استفاده می‌کند.
- تخمین زمین در قطعات ۵۱۲ پیکسلی همراه حاشیه (۲۵۶ در حافظهٔ کم) و چند thread محدودشده با بودجهٔ حافظه اجرا می‌شود. گام مدل حداقل عرض عارضه تقسیم بر ۱۲۸ است تا اندازهٔ حاشیه محدود بماند؛ گام واقعی در گزارش ثبت می‌شود.
- استخراج در پنجره‌های ۱۰۲۴ × ۱۰۲۴ است (۵۱۲ در حافظهٔ کمتر از ۲ گیگابایت)؛ کل رستر در حافظه بارگذاری نمی‌شود.
- ساخت شیپ‌فایل در قطعات ۲۵۶ × ۲۵۶ با نگهداری اتصال‌ها و قطعات روی دیسک در SQLite انجام می‌شود. مرزها در پایان برای هر عارضه ادغام می‌شوند؛ فایل موقت حذف می‌شود. علاوه بر ظرفیت رسترها، شیپ‌فایل و پایگاه موقت فضای دیسک لازم دارند که به پیچیدگی عوارض بستگی دارد.
- کش GDAL حداکثر ۲۵٪ حافظه تا سقف ۴ گیگابایت و حافظهٔ warping حداکثر ۱۲٫۵٪ تا سقف یک گیگابایت است. بودجه برای جلوگیری از مصرف تمام RAM محدود می‌شود.
- یک کار پردازشی در هر لحظه اجرا می‌شود. حداکثر سه کار، شامل بارگذاری و کار جاری، پذیرفته می‌شود. Uvicorn را با **یک worker** اجرا کنید.
- نمایش نقشه با WebGL، `powerPreference: high-performance`، نسبت پیکسل دستگاه و رسم فقط هنگام تغییر انجام می‌شود. انتخاب واقعی GPU به مرورگر و سخت‌افزار بستگی دارد؛ حالت Canvas برای نبود WebGL وجود دارد. پردازش ژئورستری با CPU انجام می‌شود و این برنامه از CUDA استفاده نمی‌کند.
- پیش‌نمایش حداکثر ۲۰۴۸ پیکسل در ضلع بلند است (۱۰۲۴ در سیستم کم‌حافظه)؛ GeoTIFF خروجی کاهش تفکیک‌پذیری ندارد. رنگ‌ها برای نمایش کشیده می‌شوند و جایگزین مقدار عددی رستر نیستند. عوارض کوچک ممکن است در پیش‌نمایش کاهش‌یافته دیده نشوند.
- پیش‌نمایش **ورودی** از Overview داخلی استفاده می‌کند، یا برای فایل‌های کوچک مستقیماً تا ضلع ۷۶۸ پیکسل خوانده می‌شود. در فایل بزرگ بدون Overview، نمای سریع با نمونه‌برداری از تعداد محدودی بلوک ساخته می‌شود و ممکن است جزئیات کوچک یا نواحی کم‌پوشش را نشان ندهد. وضوح پیش‌نمایش روی دقت استخراج و شیپ‌فایل اثر ندارد. ورودی اصلی برای ساخت Overview تغییر داده نمی‌شود.
- استفادهٔ دائمی از ۱۰۰٪ CPU/GPU تضمین نمی‌شود؛ سرعت به دیسک، فشرده‌سازی، روش تبدیل و اندازهٔ منطقه بستگی دارد.

## داده‌های موقت و استقرار

نسخهٔ نصبی نتایج موقت را در `%LOCALAPPDATA%\MSU Terrain\results` و گزارش اجرا را در `application.log` همان پوشهٔ برنامه ذخیره می‌کند. فایل‌های اصلی DSM هرگز حذف یا تغییر داده نمی‌شوند. انتخاب مستقیم دسکتاپ کپی ورودی ایجاد نمی‌کند. بارگذاری مرورگری یک بار انجام می‌شود و همان کپی برای پیش‌نمایش و استخراج دوباره استفاده می‌شود. کپی‌های بارگذاری‌شده، پیش‌نمایش‌ها و خروجی‌های موقت قدیمی‌تر از ۲۴ ساعت هنگام پذیرش کار بعدی پاک‌سازی می‌شوند؛ کارهای فعال مستثنا هستند. نتایج پوشهٔ انتخابی دائمی‌اند. حذف برنامه فایل‌های اصلی، خروجی‌های دریافت‌شده و داده‌های AppData را نگه می‌دارد. نسخهٔ سورس از `.data/` استفاده می‌کند و متغیر اختیاری `MSU_DATA_DIR` مسیر را تغییر می‌دهد.

این نسخه برای استفادهٔ شخصی یا محیط مورداعتماد آماده شده است. برای انتشار عمومی، احراز هویت، سهمیهٔ کاربران، محدودیت درخواست در reverse proxy و سیاست نگهداری داده اضافه کنید. در محیط ابری از checkout موجود استفاده کنید؛ ایجاد Git worktree نیاز نیست. فرآیند سرور پس از بازیابی snapshot باید دوباره اجرا شود.

## آزمون‌ها

```sh
uv sync --frozen
uv run pytest -q
uv run ruff check app tests
```

آزمون‌ها شامل DSM تنها، ثابت ماندن ارتفاع نسبی با تغییر مبنای مطلق، زمین شیب‌دار، اتصال بلوک‌های تخمین، زمین خارج از AOI، نبود زمین قابل مشاهده، مرز بالای ۳۰ تا ۱۰۰۰۰ متر، ارتفاع منفی از سطح دریا، مرز آستانه، NoData، ماسک داخلی، واحد فوت و scale/offset، تبدیل ۱۰ متر و نیم‌متر، CRS متفاوت، شیپ‌فایل و حفره‌ها، فایل خراب، API، ZIP64 جریانی و حفظ پوشهٔ خروجی هستند. آزمون مقیاس بزرگ، فایل sparse با اندازهٔ منطقی ۱۲۸ گیبی‌بایت و پردازش محدوده‌ای از شبکهٔ BigTIFF با بیش از ۳۴ میلیارد پیکسل را بررسی می‌کند. این فایل‌های آزمایشی فضای واقعی کمی اشغال می‌کنند؛ آزمون حاضر سنجش سرعت پردازش کامل ۱۰۰ گیگابایت دادهٔ واقعی نیست. مسیر قدیمی دو ورودی در API برای سازگاری و آزمون رگرسیون حفظ شده است؛ رابط دسکتاپ فقط DSM می‌گیرد.

آزمون مرورگر در حالی که برنامه با `--port 8000 --no-browser` اجراست:

```sh
uv sync --frozen --group browser
# Chromium موجود استفاده می‌شود؛ مسیر پیش‌فرض /usr/bin/chromium است.
# متغیر CHROMIUM_PATH مسیر اجرایی دیگری را تعیین می‌کند.
uv run --group browser python tests/browser_smoke.py
```

آزمون مرورگر درخواست‌های خارجی را مسدود می‌کند و نمونه، بارگذاری یک DSM نیم‌متری، پیش‌نمایش ورودی و زمین تخمینی، جدول ویژگی‌ها، محدوده از ZIP و اجزای شیپ‌فایل، مقادیر رستر خروجی، دریافت ZIP، بازیابی پس از refresh، اعتبارسنجی، تغییر لایه، بزرگ‌نمایی و چهار عرض نمایش را بررسی می‌کند. تصاویر در `test-results/` ذخیره می‌شوند. WebGL در headless ممکن است از renderer نرم‌افزاری استفاده کند؛ عبور این آزمون بنچمارک GPU فیزیکی نیست.

## بازسازی بستهٔ ویندوز

```sh
# Linux build host: Python 3.12, MinGW-w64, NSIS >= 3.11
python tools/build_installer.py
```

این مرحله مخصوص سازنده و نیازمند اینترنت برای دریافت اولیهٔ منابع است. ابزار از NuGet رسمی Python Software Foundation و PyPI دانلود می‌کند و hashهای قفل‌شده در `packaging/windows-lock.json` را کنترل می‌کند. راه‌انداز بومی x64 با MinGW و آیکون برنامه ساخته می‌شود؛ NSIS نصاب و حذف‌کنندهٔ آفلاین را در `downloads/` تولید می‌کند. `--cache` محل منابع ذخیره‌شده و `--tool-root` ریشهٔ ابزارهای Debian استخراج‌شده را می‌پذیرد. برای بستهٔ ZIP نیز `tools/build_windows_bundle.py` در دسترس است. هیچ دادهٔ کاربر، محیط مجازی توسعه یا تنظیمات احراز هویت داخل نصاب قرار نمی‌گیرد.
